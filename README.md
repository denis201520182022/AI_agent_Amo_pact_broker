# AI Broker — Интеллектуальный чат-бот для кредитного брокера

> Автоматизированный AI-ассистент для первичной квалификации клиентов, сбора анкетных данных и интеграции с CRM-системой.

---

## О проекте

**AI Broker** — это интеллектуальный диалоговый бот, который ведёт клиентов по сложному сценарию консультанта кредитного брокера. Бот самостоятельно:

- Квалифицирует клиента и определяет потребность
- Проверяет стоп-факторы (стаж, просрочки, ФССП, МФО, банкротство)
- Подбирает оптимальный кредитный продукт
- Собирает анкету и кредитные отчёты из БКИ
- Интегрируется с amoCRM для передачи квалифицированного лида

Всё это происходит в рамках чата на платформе **Pact.im**, а ответы генерируются от лица оператора «Татьяны» с помощью AI.

## Возможности

### 🤖 Двухуровневая AI-архитектура

- **AI-1 Анализатор** — извлекает структурированные данные из сообщений пользователя через Pydantic-схемы (имя, телефон, город, тип кредита, стоп-факторы)
- **AI-2 Генератор** — формирует естественный ответ от имени оператора, учитывая контекст и текущий этап диалога

### 📋 Сценарный диалоговый граф

Бот покрывает полный цикл консультанта:

| Этап | Описание |
|------|----------|
| **Согласие** | Получение согласия на обработку персональных данных (ОПД) |
| **Анкета** | Сбор контактных данных: имя, телефон, город |
| **Меню** | 4 направления: Кредит, Авторский курс, Платная консультация, Стоимость услуг |
| **Стоп-факторы** | 5-уровневая проверка рисков (стаж → просрочки → ФССП → МФО → банкротство) |
| **Квалификация** | Предложение залога при наличии рисков |
| **Детализация** | Сбор параметров по 5 типам кредитования |
| **Документы** | Запрос и подсчёт отчётов из 3 БКИ |
| **Передача** | Перевод квалифицированного клиента менеджеру |

### 🔄 Интеграция с экосистемой

- **Pact.im** — платформа коммуникаций, входящие и исходящие сообщения
- **amoCRM** — автоматическое создание сделок в нужной воронке, обновление статусов, заметки с анкетами
- **Telegram** — алерты, отчёты, карточки диалогов для администратора
- **OpenAI GPT** — AI-анализ и генерация ответов

### 💰 Биллинг и мониторинг

- Автоматическое списание средств за каждый диалог
- Контроль баланса и алерты при приближении к порогу
- Логирование всех запросов к LLM (модель, токены, стоимость)
- Административный Telegram-бот для управления тарифами

### ⏰ Умные напоминания

Система 7-уровневых напоминаний с адаптивными интервалами (от 5 минут до 48 часов), фильтром по рабочему времени и сбросом при получении ответа.

## Архитектура

### Высокоуровневый обзор

Проект построен на принципе разделения ответственности между независимыми сервисами:

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   Pact.im   │     │  amoCRM     │     │  OpenAI     │
│  (клиенты)  │     │   (CRM)     │     │   (AI)      │
└──────┬──────┘     └──────┬──────┘     └──────┬──────┘
       │                   │                   │
       ▼                   ▼                   ▼
┌──────────────────────────────────────────────────────┐
│                   AI Broker                          │
│                                                      │
│  ┌─────────────┐   ┌─────────────┐   ┌────────────┐ │
│  │   API       │   │   Worker    │   │ Reminder   │ │
│  │  (FastAPI)  │──▶│  (TaskIQ)   │   │   Worker   │ │
│  │  вебхуки    │   │  граф       │   │  напоминания│ │
│  └──────┬──────┘   └──────┬──────┘   └────────────┘ │
│         │                 │                          │
│    ┌────┴────┐     ┌─────┴─────┐                     │
│    │ Redis   │     │ PostgreSQL│                     │
│    │ буфер   │     │ диалоги   │                     │
│    └─────────┘     └───────────┘                     │
└──────────────────────────────────────────────────────┘
```

### Сервисы

| Сервис | Роль |
|--------|------|
| **API** | Приём вебхуков от Pact.im и amoCRM, REST API |
| **Worker** | Асинхронная обработка диалогов через LangGraph StateGraph |
| **Reminder Worker** | Периодические напоминания клиентам |
| **Admin Bot** | Telegram-панель управления для администратора |

### Ключевые архитектурные решения

**LangGraph StateGraph для управления диалогами**

Диалоговый процесс реализован как направленный граф с тремя узлами:

```
[analyze] → [logic] → [generate] → END
```

Каждый узел отвечает за свой этап: анализ сообщения, обновление состояния, генерация ответа. Состояние персистентно хранится в PostgreSQL.

**Debounce-буферизация**

Входящие сообщения агрегируются в Redis-буфер на 10 секунд — AI получает полные ответы пользователя, а не отдельные слова.

**JSONB для гибкой схемы данных**

История диалогов и извлечённые данные хранятся в JSONB-полях, что позволяет гибко добавлять новые поля без миграций.

**Конфигурация через YAML**

Все промпты, бизнес-правила и параметры диалогов вынесены в отдельные YAML-файлы — логика меняется без деплоя кода.

## Технологии

| Категория | Технологический стек |
|-----------|---------------------|
| **Язык** | Python 3.11 |
| **Веб-фреймворк** | FastAPI + Uvicorn |
| **AI-оркестрация** | LangGraph, LangChain |
| **LLM** | OpenAI GPT-4o-mini (structured + free-text) |
| **Боты** | Aiogram (Telegram) |
| **База данных** | PostgreSQL 15, SQLAlchemy (async) |
| **Кэш / очереди** | Redis 7, TaskIQ |
| **Миграции** | Alembic |
| **HTTP-клиент** | httpx с retry-логикой (tenacity) |
| **Конфигурация** | Pydantic Settings, PyYAML |
| **Валидация** | Pydantic v2 |
| **Контейнеризация** | Docker, Docker Compose |
